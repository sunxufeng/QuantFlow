# QuantFlow V1.1.0

在 V1.0 稳定可用的基础上，补齐「策略生成智能化 + 集成调用 + 数据工程」三类能力，形成「自然语言出策略 → 因子/回测验证 → API/通知接入」的闭环。

## 里程碑交付

### N1 · LLM 策略助手
- `core/llm` Provider 抽象层：`MockProvider`（确定性、免 key、可演示）+ `OpenAIProvider`（OpenAI 兼容 `/chat/completions`，支持 DeepSeek/通义/自建网关）
- `llm.assistant` 节点：可在 DAG 内调用 LLM，无 key 时自动走 Mock
- `POST /api/llm/assist`（鉴权）+ `GET /api/llm/status`
- 配置：`QF_LLM_PROVIDER` / `QF_LLM_API_KEY` / `QF_LLM_BASE_URL` / `QF_LLM_MODEL`
- 说明：真实大模型需提供 `QF_LLM_API_KEY` 并切 `QF_LLM_PROVIDER=openai` 激活；当前默认 Mock

### N2 · API 代码式调用
- Python SDK 包 + API Token 双鉴权体系（Token / JWT）
- OpenAPI 自动生成文档

### N3 · 因子分析模块独立
- 独立因子库 `app/factors`（RankIC / ICIR / 衰减 / 分层收益 / 自相关）
- 节点重构复用因子库
- `POST /api/factors/analyze`

### N4 · 数据自动更新
- APScheduler 定时全量行情同步 + 更新状态监控（`/market/sync/status`）
- `QF_DISABLE_SCHEDULER` 可关定时任务，改为手动触发

### N5 · 通知渠道
- 通知抽象层 + Webhook（通用 JSON）+ 飞书（webhook 签名）渠道
- `notification_channels` 表 + `POST /api/notifications` CRUD + `{id}/test`
- 运行结束（成功/失败）自动触发推送
- 修复：运行完成通知此前因导入路径错误静默失效（已加回归测试）

### N6 · 分布式 Worker
- SQLite 共享任务队列 / 运行态 / 事件日志（`run_jobs` / `runs` / `run_events`），零新依赖
- `quantflow-worker` systemd 单元：原子认领 + 超时回收（stale）+ 执行落库
- `RunService` 可插拔 `backend=local|worker`（local 默认，零行为变化）
- WebSocket 改为轮询共享事件日志，跨进程实时

## 质量门禁
- 后端测试 **272 passed**（V1.0 基线 217 → V1.1 +55）
- 生产冒烟全绿（健康 / 鉴权 / Token / 行情同步 / 因子分析 / 通知 / LLM 助手 / worker 执行）
