# QuantFlow 部署手册

> 适用版本：V1.2 ｜ 更新日期：2026-08-13

QuantFlow = FastAPI 后端（:8000）+ 前端静态服务（nginx / Node :8080）。三种部署方式：

| 方式 | 适用场景 | 说明 |
|---|---|---|
| 本地开发 | 开发调试 | uvicorn + vite dev server |
| Docker Compose | 快速体验/隔离环境 | 一键 `docker compose up` |
| systemd + venv | 生产服务器 | 国内服务器推荐（避开 Docker Hub 拉取问题） |
| Kubernetes | 集群 / 多副本弹性 | `deploy/k8s/` 下 Helm-free 原生清单 + kustomize（V1.2 新增） |

---

## 一、环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `QF_MARKET_PROVIDER` | `tushare` | 行情源：`tushare` / `fixture`（内置离线数据，无需 token） |
| `QF_TUSHARE_TOKEN` | 空 | tushare token（provider=tushare 时必填） |
| `QF_DB_PATH` | `backend/data/quantflow.db` | SQLite 路径 |
| `QF_SECRET_KEY` | 开发默认值 | **生产必改**（`openssl rand -hex 32`） |
| `QF_TOKEN_EXPIRE_MINUTES` | `1440` | JWT 有效期（分钟） |
| `QF_CORS_ORIGINS` | 本地 5173 | 逗号分隔白名单 |
| `QF_DEBUG` | `1` | 生产设 `0` |
| `QF_BACKEND_PORT` / `QF_FRONTEND_PORT` | 8100 / 8080 | deploy.sh 端口覆盖 |
| `QF_DISABLE_SCHEDULER` | `0` | 设 `1` 关闭 APScheduler 定时行情同步（手动触发） |
| `QF_RUN_BACKEND` | `local` | 运行后端：`local`（进程内线程池）/ `worker`（API 入队，由 `quantflow-worker` 进程消费） |
| `QF_WORKER_POLL_INTERVAL` | `1` | worker 轮询间隔（秒） |
| `QF_WORKER_STALE_TIMEOUT` | `300` | worker 认领超时回收（秒） |
| `QF_LLM_PROVIDER` | `mock` | LLM provider：`mock`（确定性免 key）/ `openai`（OpenAI 兼容） |
| `QF_LLM_API_KEY` | 空 | OpenAI 兼容 key（provider=openai 时必填） |
| `QF_LLM_BASE_URL` | `https://api.openai.com/v1` | OpenAI 兼容 base url（DeepSeek/通义/自建网关） |
| `QF_LLM_MODEL` | `gpt-4o-mini` | 模型名 |

## 二、本地开发

```bash
# 后端（端口 8000）
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
QF_MARKET_PROVIDER=fixture .venv/bin/uvicorn app.main:app --reload --port 8000

# 前端（端口 5173，/api 代理到 8000）
cd frontend && npm install && npm run dev
# 打开 http://localhost:5173 ，首个注册用户自动成为 admin
```

## 三、Docker Compose

```bash
cd quantflow
# 生产务必先设置强密钥：
export QF_SECRET_KEY=$(openssl rand -hex 32)
docker compose -f deploy/docker-compose.yml up -d --build
# 前端 http://localhost:8080 ；SQLite 持久化在 named volume quantflow-data
```

服务拓扑：`frontend(nginx :80 → 宿主 8080) → /api/* 反代 → backend(uvicorn :8000) → SQLite`

```bash
docker compose -f deploy/docker-compose.yml logs -f backend   # 后端日志
docker compose -f deploy/docker-compose.yml down              # 停止（保留数据）
docker compose -f deploy/docker-compose.yml down -v           # 停止并清空数据
```

## 四、生产部署（systemd + venv，推荐）

### 4.1 首次部署

```bash
cd quantflow
sudo bash deploy/deploy.sh        # 安装到 /opt/quantflow/QuantFlow 并注册 systemd
```

部署脚本默认：后端 venv + uvicorn `127.0.0.1:8100`，前端 `node server.mjs` `0.0.0.0:8080`。

### 4.2 升级部署（拉取新代码）

服务器网络可能无法直连 `github.com`，用 `api.github.com` 的 codeload 通道：

```bash
cd /tmp && rm -rf qf_src && mkdir qf_src
curl -sL https://codeload.github.com/sunxufeng/QuantFlow/tar.gz/refs/heads/main | tar xz -C qf_src --strip-components=1
cd /tmp/qf_src && tar czf /tmp/qf_pkg.tgz \
  --exclude=.git --exclude=.venv --exclude=node_modules --exclude=dist --exclude=backend/data .
cd /opt/quantflow/QuantFlow && tar xzf /tmp/qf_pkg.tgz
# 若依赖有更新：
/opt/quantflow/QuantFlow/backend/.venv/bin/pip install --no-cache-dir \
  -i https://mirrors.aliyun.com/pypi/simple/ -r /opt/quantflow/QuantFlow/backend/requirements.txt
```

前端构建产物不入库：本地 `npm run build` 后把 `frontend/dist` 打包传服务器覆盖即可（`node server.mjs` 直接托管 dist）。

### 4.3 systemd 单元

`/etc/systemd/system/quantflow.service`（后端）：

```ini
[Service]
Type=simple
WorkingDirectory=/opt/quantflow/QuantFlow/backend
Environment=QF_DEBUG=0
Environment=QF_MARKET_PROVIDER=fixture
Environment=QF_SECRET_KEY=REPLACE_ME_openssl_rand_hex_32
Environment=QF_CORS_ORIGINS=https://你的域名,http://116.62.188.165:8080
ExecStart=/opt/quantflow/QuantFlow/backend/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8100
Restart=on-failure
```

`/etc/systemd/system/quantflow-frontend.service`（前端 + API 反代）：

```ini
[Service]
WorkingDirectory=/opt/quantflow/QuantFlow/frontend
ExecStart=/usr/bin/node /opt/quantflow/QuantFlow/frontend/server.mjs
Restart=on-failure
```

```bash
systemctl daemon-reload && systemctl restart quantflow quantflow-frontend
systemctl status quantflow
curl http://127.0.0.1:8100/api/health
```

### 4.3.1 V1.1 分布式 Worker（可选）

V1.1 起运行后端支持 `worker` 模式：API 仅把工作流入队共享 SQLite 任务表（`run_jobs`），由独立 `quantflow-worker` 进程消费执行，运行态/事件落共享库，可水平扩展。

1. 后端单元设 `Environment=QF_RUN_BACKEND=worker`（与 worker 共享同一 `QF_DB_PATH`）。
2. 新增 `/etc/systemd/system/quantflow-worker.service`：

```ini
[Unit]
Description=QuantFlow distributed worker (V1.1)
After=network.target quantflow.service
Requires=quantflow.service

[Service]
Type=simple
WorkingDirectory=/opt/quantflow/QuantFlow/backend
Environment=QF_MARKET_PROVIDER=fixture
Environment=QF_WORKER_POLL_INTERVAL=1
Environment=QF_WORKER_STALE_TIMEOUT=300
ExecStart=/opt/quantflow/QuantFlow/backend/.venv/bin/python -m app.core.worker
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now quantflow-worker.service
journalctl -u quantflow-worker.service -f   # 观察认领/执行日志
```

> 回退：`QF_RUN_BACKEND` 不设或设 `local` 即恢复进程内线程池执行（零行为变化）。
> 通知渠道（Webhook/飞书）与 LLM 策略助手（mock/openai）见各自 API；运行结束自动推送通知与 `QF_LLM_*` 配置同上。

### 4.4 对外 HTTPS（Nginx Proxy Manager 示例）

## 六、Kubernetes 部署（V1.2 新增）

原生 YAML 清单（无 Helm 依赖），位于 `deploy/k8s/`，通过 kustomize 一键交付。

### 6.1 资源清单

| 文件 | 资源 | 说明 |
|---|---|---|
| `namespace.yaml` | Namespace `quantflow` | 隔离命名空间 |
| `configmap.yaml` | ConfigMap `quantflow-config` | 非敏感环境变量（行情源 / worker 参数 / DB 路径） |
| `secret.yaml` | Secret `quantflow-secret` | `QF_SECRET_KEY`（**占位符，生产务必覆盖**） |
| `pvc.yaml` | PVC `quantflow-data` | SQLite 持久化（1Gi，RWO） |
| `backend-deployment.yaml` | Deployment `quantflow-backend` | uvicorn :8000，liveness/readiness 探针 `/api/health` |
| `backend-service.yaml` | Service `backend` | ClusterIP :8000（前端 nginx 经 `backend:8000` 反代） |
| `worker-deployment.yaml` | Deployment `quantflow-worker` | `python -m app.core.worker`，共享 PVC |
| `frontend-deployment.yaml` | Deployment `quantflow-frontend` | nginx :80 静态站 + `/api` 反代 |
| `frontend-service.yaml` | Service `frontend` | NodePort（云环境可改 LoadBalancer） |
| `ingress.yaml` | Ingress `quantflow-ingress` | 可选，需 ingress-nginx 控制器 |
| `kustomization.yaml` | Kustomization | `kubectl apply -k .` 批量交付 |
| `deploy.sh` | 辅助脚本 | build / apply / status / delete |

### 6.2 部署步骤

```bash
cd deploy/k8s

# 1) （可选）构建并推送镜像到集群可访问的 registry
#    QUANTFLOW_REGISTRY=registry.example.com/quantflow/ ./deploy.sh build
./deploy.sh build

# 2) 生产务必覆盖密钥
kubectl -n quantflow create secret generic quantflow-secret \
  --from-literal=QF_SECRET_KEY="$(openssl rand -hex 32)" \
  --dry-run=client -o yaml | kubectl apply -f -

# 3) 应用全部资源
./deploy.sh apply

# 4) 查看状态
./deploy.sh status
```

### 6.3 访问

- **NodePort**：`kubectl -n quantflow get svc frontend` 取 `NODEPORT`，浏览器访问 `http://<节点IP>:<NODEPORT>`。
- **LoadBalancer**：把 `frontend-service.yaml` 的 `type` 改为 `LoadBalancer`，取 EXTERNAL-IP。
- **Ingress**：部署 ingress-nginx 后应用 `ingress.yaml`，绑 `quantflow.example.com`。

### 6.4 注意事项

- **SQLite + RWO 卷**：backend 与 worker 共享同一 PVC，仅保证二者调度到同一节点时正常。多节点生产环境建议改用网络数据库（Postgres / 云数据库）或独立存储。
- **镜像 tag**：默认 `:latest`；生产应构建带版本号的 tag（如 `quantflow-backend:1.2.0`）并固定 `image` 字段。
- **Secret**：`secret.yaml` 内为演示占位符，任何非演示环境必须先覆盖 `QF_SECRET_KEY`。
- **副本数**：当前 backend / worker / frontend 各 1 副本；backend 有状态（SQLite）不宜简单扩副本，worker 可随队列压力水平扩展。

## 7. LLM 策略助手激活（V1.1 N1）

`/api/llm/assist` 提供对话式策略建议，前端「LLM 助手」页可用。**默认 mock 模式**（无需 key，输出确定性结构化建议，便于演示与测试）。

### 7.1 启用真实大模型

设置以下环境变量后重启 backend（`app.core.llm.get_provider()` 按环境切换）：

| 变量 | 说明 | 默认 |
| --- | --- | --- |
| `QF_LLM_PROVIDER` | `mock`（默认）或 `openai` | `mock` |
| `QF_LLM_API_KEY` | OpenAI 兼容协议的 API Key | 空 |
| `QF_LLM_BASE_URL` | 网关地址（DeepSeek / 通义 / 自建均兼容） | `https://api.openai.com/v1` |
| `QF_LLM_MODEL` | 模型名 | `gpt-4o-mini` |
| `QF_LLM_TEMPERATURE` / `QF_LLM_MAX_TOKENS` | 采样参数 | `0.2` / `1024` |

判断逻辑：仅当 `QF_LLM_PROVIDER=openai` **且** `QF_LLM_API_KEY` 非空时走真实 provider；否则回退 mock。前端「LLM 助手」页会显示当前 provider 与是否已配置真实模型。

### 7.2 各部署方式落地

- **systemd（当前生产）**：在 `quantflow.service` 的 `[Service]` 段加 `Environment=QF_LLM_PROVIDER=openai` 等，再 `systemctl restart quantflow.service`。
- **Docker Compose**：在 `backend` 服务的 `environment:` 中加上述变量。
- **K8s**：`deploy/k8s/configmap.yaml` 已含 `QF_LLM_PROVIDER` / `QF_LLM_API_KEY` 等占位；`backend-deployment.yaml` 通过 `envFrom: configMapRef` 注入。建议把 `QF_LLM_API_KEY` 改为从 `Secret` 引用（见 `secret.yaml`），而非明文写 ConfigMap。改后 `kubectl -n quantflow apply -f deploy/k8s/configmap.yaml && kubectl -n quantflow rollout restart deployment/backend`。
